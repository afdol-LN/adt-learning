PSU Adaptive Learning System (PSU ALS)

สถานะ: ฉบับสมบูรณ์ สร้าง: 2026-07-02 อัปเดต: 2026-07-02

0. วัตถุประสงค์ของเอกสาร

เอกสาร Product Requirements Document (PRD) ฉบับนี้อธิบายข้อกำหนดด้านฟังก์ชัน เส้นทางการใช้งานของผู้ใช้ ตัวชี้วัดความสำเร็จ และขอบเขต MVP ของ PSU Adaptive Learning System (PSU ALS) เพื่อให้ PM, UX designer, system architect และ developer เข้าใจภาพผลิตภัณฑ์ตรงกัน เอกสารใช้คำศัพท์กลางเพื่อลดความคลุมเครือ และกำหนด requirement ด้วยรหัสที่อ้างอิงได้คงที่ตั้งแต่ FR-1.1 ถึง FR-5.2 รวมถึงระบุสมมติฐานสำคัญด้วย [ASSUMPTION]

ข้อมูลอ้างอิง: เอกสารนี้ต่อยอดจาก prototype ฝั่ง frontend แบบ React + Vite ในโฟลเดอร์ go6-prototype และ schema ฐานข้อมูล TypeORM ที่ออกแบบสำหรับ NestJS

1. วิสัยทัศน์

หลักสูตรการเขียนโปรแกรมแบบเดียวกันสำหรับทุกคนมักไม่ตอบโจทย์นักศึกษาที่มีพื้นฐานต่างกัน ส่งผลให้บางคนตามไม่ทัน ขณะที่บางคนที่เก่งอยู่แล้วรู้สึกเสียเวลากับเนื้อหาพื้นฐานซ้ำ ๆ

PSU Adaptive Learning System (PSU ALS) แก้ปัญหานี้ด้วยวงจรการเรียนรู้แบบปรับตัวได้ ซึ่งปรับจังหวะและเนื้อหาให้เหมาะกับผู้เรียนแต่ละคน ระบบลดองค์ประกอบเกมที่ไม่จำเป็น เช่น level ตัวละครหรือกราฟิก RPG เพื่อให้ผู้เรียนโฟกัสกับการเติบโตของความเข้าใจเชิงแนวคิด

ผู้เรียนจะเรียนผ่าน Concept Map หรือ Skill Tree ซึ่งเป็นกราฟแนวคิดแบบ directed acyclic graph ที่ปลดล็อก node ตามความก้าวหน้า ระบบใช้ Bayesian Knowledge Tracing (BKT) Mastery Engine เพื่อติดตามความน่าจะเป็นว่าผู้เรียนเชี่ยวชาญแนวคิดนั้นแล้ว และใช้ Case-Based Reasoning (CBR) เพื่อเลือกเส้นทางคำถามที่เหมาะสม ทำให้ผู้เรียนได้รับ micro-exercise ที่พอดีกับระดับความสามารถของตนเอง

2. ผู้ใช้เป้าหมาย

2.1 งานที่ผู้ใช้ต้องการทำให้สำเร็จ

  • เรียนตามจังหวะของตัวเอง: ในฐานะนักศึกษาชั้นปีที่ 2 สาขา CS/ICT ฉันต้องการเรียนแนวคิดการเขียนโปรแกรมด้วยความเร็วที่เหมาะกับตัวเอง เพื่อไม่ให้รู้สึกตามไม่ทันหรือเบื่อ
  • ตรวจคำตอบได้ทันที: ในฐานะนักศึกษา ฉันต้องการทดสอบความเข้าใจเรื่อง code block และได้รับคะแนนหรือ feedback ทันที เพื่อแก้ความเข้าใจผิดได้เร็ว
  • ประเมินด้วยการลงมือทำ: ในฐานะผู้ใช้ ฉันต้องการข้าม lecture วิดีโอยาว ๆ และพิสูจน์ความสามารถผ่านแบบฝึกโต้ตอบโดยตรง
  • พัฒนาเฉพาะจุดอ่อน: ในฐานะผู้เรียน ฉันต้องการให้ระบบวิเคราะห์จุดอ่อนและส่งแบบฝึกที่ช่วยแก้ช่องว่างนั้นโดยตรง

2.2 กลุ่มที่ไม่ใช่ผู้ใช้หลักใน v1

  • อาจารย์ที่ต้องการระบบสร้างคำถาม: MVP โฟกัสที่การเรียนของนักศึกษาและการคำนวณ session เท่านั้น การแก้ concept node หรือ question bank จะทำผ่านฐานข้อมูลโดยตรง
  • ผู้เริ่มต้นแบบไม่มีพื้นฐานเลย: ระบบนี้ออกแบบสำหรับนักศึกษาที่มีพื้นฐานเบื้องต้นเรื่อง variables และ operations แล้ว โดยทำหน้าที่เป็น adaptive coach เสริม

2.3 เส้นทางการใช้งานสำคัญ

UJ-1: Afdol เริ่มจาก Pretest เพื่อข้ามพื้นฐานเรื่องตัวแปร
Afdol, นักศึกษา ICT ปี 2 ที่รู้เรื่อง Python variables แล้ว · เข้าสู่ระบบแล้ว อยู่ที่หน้า GetStart

Afdol เริ่ม session การเรียนและเลือก Pretest Gateway ระบบแสดงคำถาม diagnostic 5 ข้อ ครอบคลุม variables, loops, functions, sorting และ graphs เขาตอบถูก 3 ข้อ ระบบนำความถูกต้องและเวลาในการตอบไปตั้งค่า BKT mastery probability เริ่มต้นให้อยู่ในระดับ Level 2 (Core) จากนั้น Afdol เข้าสู่ Home dashboard โดย tier Foundation (T1) ถูก mark ว่าสำเร็จ 100% และปลดล็อก variables, operators และ basic I/O เขาจึงไปเริ่มเรียน Loops ได้ทันที

กรณีขอบ: หาก Afdol ออกจากแอปกลางคัน คำตอบจะถูก cache ไว้ ทำให้กลับมาทำต่อหรือ submit pretest ได้เมื่อ login ใหม่

UJ-2: นักศึกษากด concept node ที่ยังล็อกอยู่ และถูกพาไปดู prerequisite
Student, ต้องการเรียน OOP inheritance · อยู่ที่ Dashboard และ Interactive Concept Map

นักศึกษาดู Concept Map และอยากข้ามไปเรียน OOP จึงคลิก node OOP - Inheritance ที่ยังล็อกอยู่ ระบบเปิด Details Side Panel พร้อมสถานะ locked และแสดง prerequisite ได้แก่ Linked List และ Recursion ปุ่ม "Go to Exercise" ถูก disable เมื่อคลิก prerequisite link ระบบ highlight เส้นเชื่อมใน SVG map และเลื่อน panel ไปยัง concept นั้น

3. คำศัพท์สำคัญ

Concept Node (Skill) - หน่วยการเรียนรู้หนึ่ง node ในต้นไม้ เช่น Loops โดยมีค่า mastery probability P(L_t), progress 0-100% และ dependency link
Prerequisite - เส้นเชื่อมแบบมีทิศทางใน map ที่บอกว่า node แม่ต้องมี progress อย่างน้อย 60% ก่อน node ลูกจึงจะปลดล็อก
Mastery Probability P(L_t) - ความน่าจะเป็นแบบ Bayesian ช่วง 0.0 ถึง 1.0 ที่บอกว่านักศึกษาเชี่ยวชาญ concept ใน node นั้นแล้วมากน้อยแค่ไหน
Concept Map (Skill Tree) - โครงสร้างหลักสูตรแบบ DAG ที่แสดงเป็นแผนภาพ node สีต่าง ๆ ตามสถานะ
Micro-Exercise - ข้อฝึกโต้ตอบขนาดเล็ก เช่น multiple choice หรือเติม code snippet ในช่องว่าง
Session - การทำแบบฝึกของนักศึกษาใน Concept Node หนึ่ง ๆ โดยประกอบด้วยคำถาม 5 ข้อ
Behavior Profile - การจัดกลุ่มพฤติกรรมการเรียน เช่น Mastery, Fast, Steady, Slow, Struggler จากเวลา ความถูกต้อง และ momentum

4. ฟีเจอร์

4.1 Student Pre-test Gateway

คำอธิบาย: ประเมินระดับเริ่มต้นของผู้ใช้ เพื่อให้ข้าม concept ที่ซ้ำซ้อนกับความรู้เดิมได้ รองรับ UJ-1

FR-1.1: การทำ Pre-test และการให้คะแนน

ระบบต้องแสดง pretest จำนวน 5 ข้อ ครอบคลุม tier T1 ถึง T3 และนักศึกษาจะย้อนกลับไปแก้คำตอบที่ submit แล้วไม่ได้

ผลลัพธ์ที่ทดสอบได้
  • หากนักศึกษากด Next โดยยังไม่เลือกคำตอบ ระบบต้องแสดง warning modal
  • ระบบต้องบันทึก timestamp ของการ submit แต่ละข้อ เพื่อใช้คำนวณ metric ด้านเวลา
FR-1.2: การตั้งค่า BKT probability เริ่มต้น

ระบบต้องคำนวณและกำหนดค่า initial concept mastery probability P(L_0) แบบ dynamic โดยรวมผล pre-test ทั้งความถูกต้องและเวลาเข้ากับข้อมูล profile เช่น learning goal, academic year และระดับ familiarity/experience ที่ผู้ใช้กรอก

[ASSUMPTION: Dynamic BKT Onboarding Calibration] ค่า P(L_0) คำนวณจาก P_base(Familiarity) + Delta P(Pretest) + Delta P(Profile) โดย Familiarity map เป็น Novice (0.15), Intermediate (0.45), Advanced (0.75); Pretest เพิ่มได้สูงสุด +0.15 จากความถูกต้องและความเร็ว; Profile เพิ่มได้สูงสุด +0.09 จากความเกี่ยวข้องกับ ICT/CS และการอยู่ชั้นปี 2 ขึ้นไป
ผลลัพธ์ที่ทดสอบได้
  • เมื่อทำ pretest เสร็จ ระบบต้องอัปเดต conceptMapState ใน profile โดยตั้ง progress ของ node ที่ข้ามได้เป็น 100% และปลดล็อก node ที่ขึ้นต่อจาก node เหล่านั้น

4.2 Interactive Concept Map (Skill Tree)

คำอธิบาย: แสดงแผนภาพหลักสูตรให้เห็นว่า path ไหนเรียนได้แล้วหรือยังล็อกอยู่ รองรับ UJ-2

FR-2.1: การ render graph และ layout

UI ต้องแสดง node ด้วย style ที่แตกต่างกันตามสถานะ ได้แก่ Locked, Available และ Mastered

ผลลัพธ์ที่ทดสอบได้
  • node ที่ล็อกต้องแสดงไอคอน lock ข้อความสีเทา และ disable ปุ่ม Start ใน side panel
FR-2.2: Node Detail Side Panel

เมื่อคลิก node ที่ปลดล็อกแล้วหรือ node ที่สามารถปลดล็อกได้ ระบบต้องเลื่อน panel รายละเอียดเข้ามา โดยแสดง mastery probability P(L_t), progress ปัจจุบัน, prerequisites และ descendant nodes

4.3 Bayesian Knowledge Tracing (BKT) Mastery Engine

คำอธิบาย: ประเมินความน่าจะเป็นว่านักศึกษาเชี่ยวชาญ concept แต่ละตัว หลังตอบ exercise แต่ละข้อ รองรับ UJ-1 และ UJ-2

FR-3.1: การประมาณ latent state

ระบบต้องคำนวณ probability of mastery P(L_t) สำหรับ Concept Node ที่ใช้งานอยู่หลังผู้เรียนทำ micro-exercise เสร็จ โดยใช้สูตรมาตรฐานของ BKT Bayes สำหรับทั้งกรณีตอบถูกและตอบผิด

[ASSUMPTION: BKT Node Mastery Threshold] นักศึกษาจะถือว่าเชี่ยวชาญ concept node เมื่อค่า mastery probability P(L_t) มากกว่าหรือเท่ากับ 0.95 หรือ 95%
FR-3.2: การปลดล็อก Concept Node ต่อเนื่อง

เมื่อ mastery probability P(L_t) ของนักศึกษามากกว่าหรือเท่ากับ 0.95 ระบบต้องตั้ง progress ของ node เป็น 100% เปลี่ยนสถานะเป็น completed และอัปเดต descendant nodes ทั้งหมดให้เป็น unlocked

4.4 Interactive Micro-Exercises Loop

คำอธิบาย: ขับเคลื่อน game loop latency ต่ำด้วย Socket.IO gateway

FR-4.1: WebSocket Gateways

แบบฝึกต้องทำงานบน WebSocket connection ที่คงอยู่ เพื่อรองรับการส่งคำถามและตัวจับเวลาแบบ real-time

[ASSUMPTION: String Verification] แบบฝึกใน MVP จะตรวจ code blanks ด้วย string matching แทนการรัน arbitrary code ใน sandbox container
FR-4.2: การประเมินผลแบบ Real-time

คำตอบของผู้ใช้ต้องถูก validate, record และส่งผลลัพธ์กลับภายใน 50ms

4.5 BKT-Based Adaptive Recommendation Engine

คำอธิบาย: ประสานการเลือกคำถามและอัปเดตสถิติ mastery ของนักศึกษาเมื่อ session สิ้นสุด

FR-5.1: การเลือกเส้นทางตาม Mastery

ระบบต้องเลือก micro-exercise ถัดไปแบบ dynamic ด้วย Case-Based Reasoning (CBR) ให้สอดคล้องกับ mastery probability P(L_t) ปัจจุบันของนักศึกษาที่คำนวณจาก BKT engine

[ASSUMPTION: Cache Persistence] คำตอบที่อยู่ระหว่าง session และ intermediate BKT state updates จะถูกเขียนลง Redis ส่วน finalized mastery probability P(L_t) และ completion progress จะ flush ลง PostgreSQL เมื่อ session จบเท่านั้น

4.6 แผนภาพขั้นตอนการทำงานและสถาปัตยกรรมระบบ (PRD End-to-End System Workflow & Visualization)

คำอธิบาย: แสดงวงจรการทำงานครบวงจรของ PSU Adaptive Learning System ตั้งแต่ขั้นตอนการลงทะเบียนและ Pre-test ประเมินทักษะเริ่มต้น จนถึงวงจรเรียลไทม์ BKT Mastery และการบันทึกลงฐานข้อมูล

5. สิ่งที่ไม่ทำ

  • งานภาพแบบ RPG: ไม่มี character levels, custom avatars หรือ game screens
  • Media Management: ไม่ host หรือเล่นวิดีโอ lecture ยาว ๆ
  • Student Interaction: ไม่มี chat, messaging หรือ forum ใน v1
  • Code Execution Sandbox: ไม่รัน backend code block แบบ dynamic โดย v1 ใช้ string-based validation

6. ขอบเขต MVP

6.1 อยู่ในขอบเขต

  • Pre-test จำนวน 5 ข้อ
  • Dynamic Concept Map สำหรับ Python Data Structures พร้อม node สีเทา/น้ำเงิน/เขียวตามสถานะ
  • Exercise loop ผ่าน Socket.IO พร้อมตัวจับเวลาคำถามแบบ real-time
  • Bayesian Knowledge Tracing (BKT) Mastery Engine เพื่อติดตาม probability ของ concept mastery
  • Backend แบบ NestJS monolith พร้อม PostgreSQL/TypeORM persistence และ Redis caching

6.2 อยู่นอกขอบเขต MVP

  • Adaptive SQL branch เลื่อนไปภายหลัง
  • Instructor portal สำหรับจัดการ question bank
  • Docker sandbox สำหรับรัน code
  • Machine learning SVD offline recalculations: Offline Collaborative Filtering เลื่อนไป v2; v1 ใช้ BKT + CBR

A-3
แบบฝึกใน MVP ใช้ string matching สำหรับ fill-in-the-blank snippets แทนการรัน code ใน sandbox เต็มรูปแบบ (Section 4.4)

Redis cache ข้อมูล active session และ flush ค่า BKT mastery probability ที่ finalized แล้วลง PostgreSQL เมื่อ session สิ้นสุด (Section 4.5)
