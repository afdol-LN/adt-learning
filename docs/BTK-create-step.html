Bayesian Knowledge Tracing (BKT) Engine Implementation Plan

This document outlines the step-by-step backend implementation plan to create and test the Bayesian Knowledge Tracing (BKT) Engine, strictly grounded in the data, mathematical formulas, and database constraints defined in the PRD (prd.html, prd_thai.html) and Addendum (addendum.md).

Step 1: Define BKT Interfaces & Constants (PRD & Addendum Specs)

Create src/type/bkt.interface.ts (or src/libs/bkt/bkt.interface.ts) containing the exact data structures and constants defined in the PRD:

Parameter / Constant Specification / Formula PRD / Addendum Reference
BKT Core Parameters pL0 (Initial Mastery), pG (Guess), pS (Slip), pT (Learning Transition) Addendum Section 1.1
MASTERY_THRESHOLD 0.95 (Node completed when P(Lt) ≥ 0.95) Addendum 1.1.4 & PRD 4.3
Clamping Bounds Min: 0.01 | Max: 0.99 Addendum 1.1.3
Base Familiarity (Pbase) Novice: 0.15 | Intermediate: 0.45 | Advanced: 0.75 Addendum 1.2 & PRD FR-1.2
Pretest Delta (ΔPPretest) Max +0.15 (Accuracy × 0.10 + SpeedFactor × 0.05) Addendum 1.2 & PRD FR-1.2
Profile Delta (ΔPProfile) Max +0.09 (CS/ICT Major: +0.05 | Year ≥ 2: +0.04) Addendum 1.2 & PRD FR-1.2

Step 2: Implement BKT Calculation Service (BktService)

Create src/libs/bkt/bkt.service.ts (or NestJS service src/service/bkt.service.ts) with two core methods:

A. Initial Onboarding Probability Calculator (calculateInitialProbability)

P(L0) = Pbase(Familiarity) + ΔP(Pretest) + ΔP(Profile)
  • Pretest Performance Delta: ΔP(Pretest) = (Accuracy × 0.10) + (SpeedFactor × 0.05)
    • Accuracy = correctAnswers / totalQuestions
    • SpeedFactor = max(0, min(1, (expectedTime - actualTime) / expectedTime))
  • Profile Metadata Delta:
    • Add +0.05 if Major matches CS or ICT.
    • Add +0.04 if Academic Year ≥ 2.
  • Clamp final P(L0) within [0.01, 0.99].

B. Stepwise Mastery Probability Updater (updateMasteryProbability)

Computes the updated mastery state following any micro-exercise attempt:

// 1. Bayesian Posterior Update P(Lt | Ct)
If Correct (Ct = 1):   P(Lt | Ct=1) = [P(Lt-1) · (1 - P(S))] / [P(Lt-1) · (1 - P(S)) + (1 - P(Lt-1)) · P(G)]
If Incorrect (Ct = 0): P(Lt | Ct=0) = [P(Lt-1) · P(S)] / [P(Lt-1) · P(S) + (1 - P(Lt-1)) · (1 - P(G))]

// 2. Learning Transition Step P(T)
P(Lt) = P(Lt | Ct) + (1 - P(Lt | Ct)) · P(T)

// 3. Numerical Clamping & Mastery Check
P(Lt) = max(0.01, min(0.99, P(Lt)))
isMastered = P(Lt) ≥ 0.95

Step 3: Integrate with Session Cache & Storage (PRD Section 4.5)

Per PRD constraint [ASSUMPTION: Cache Persistence]:

  1. During active micro-exercise quiz loops, store intermediate P(Lt) probabilities in Redis.
  2. When the session terminates, flush finalized P(Lt), completion progress (0-100%), and node unlock status (locked, unlocked, completed) atomically to PostgreSQL JSONB column Userprofile.conceptMapState.

Step 4: Implement Unit Tests (bkt.service.spec.ts)

Create Jest unit test file src/service/bkt.service.spec.ts (or src/libs/bkt/bkt.service.spec.ts) testing all PRD scenarios:

  • Posterior Probability Updates (updateMasteryProbability):
    • Verify answering correctly (Ct = 1) increases P(Lt) relative to P(Lt-1).
    • Verify answering incorrectly (Ct = 0) adjusts P(Lt) downwards according to Slip probability.
  • Clamping Boundary Tests:
    • Verify repeated incorrect answers never drop P(Lt) below 0.01.
    • Verify repeated correct answers never push P(Lt) above 0.99.
  • Mastery Threshold Check:
    • Verify node returns isMastered: true when P(Lt) ≥ 0.95 and isMastered: false when below 0.95.
  • Onboarding Calibration PRD Scenario Test (calculateInitialProbability):
    • Test base familiarities (0.15, 0.45, 0.75).
    • Test Afdol's scenario from PRD Section 4.1: Diagnostic pre-test (3/5 correct = 0.6 accuracy) combined with profile metadata bonuses properly calculates initial onboarding probability P(L0).
