โครงสร้าง BKT & Adaptive Learning Integration

💡 บทสรุปการเชื่อมโยงระบบ BKT (Bayesian Knowledge Tracing)

เอกสารนี้สรุปแนวคิดของระบบเดิม ทฤษฎีปรับปรุงใหม่ด้วยตัวแปรเวลา (Method 1) และการเชื่อมต่อข้อมูลประวัติเพื่ออัปเดตโมเดลออฟไลน์ด้วย pyBKT

1. คอนเซปต์ BKT & KT-IDEM ที่ใช้งานปัจจุบัน

โมเดลในระบบปัจจุบันใช้การคิดความสามารถแยกรายบุคคลสำหรับระดับความรู้ แต่ค่าพารามิเตอร์ของโจทย์จะอิงตามระดับความยากง่าย:

  • ระดับนักเรียน (Student-specific): เก็บค่าความน่าจะเป็นของความรู้รายบุคคล P(L) ของใครของมันแยกจากกันเด็ดขาด ผลสอบของนาย A จะไม่กระทบความรู้ของนาย B
  • ระดับโจทย์และทักษะ (Item & Skill Parameters): ค่า P(G) (Guess) และ P(S) (Slip) เป็นคุณสมบัติประจำข้อสอบที่ผูกอยู่กับตัวโจทย์เอง

2. แนวคิดการใช้เวลาประเมินความชำนาญ (Method 1)

หากผู้เรียนทำโจทย์ถูกแต่ใช้เวลานาน (Struggling) ระบบจะประเมินว่า "ยังไม่ชำนาญจริง" และอัปเดตความรู้ใหม่เพิ่มขึ้นน้อยกว่าคนทำที่ทำได้เร็วอย่างคล่องแคล่ว (Fluent):

สูตรการคำนวณที่เพิ่มระบบเวลา:

  1. คำนวณค่าตัวคูณความเร็ว Speed Factor (β):
    • ถ้าทำเสร็จเร็วกว่าหรือเท่ากับเวลาแนะนำ: β = 1.0
    • ถ้าทำช้ากว่าเวลาแนะนำ: β = 1.0 / (เวลาที่ใช้จริง / เวลาแนะนำ) (มีค่าต่ำสุดที่ 0.1)
  2. นำค่า β ไปคูณลดทอนอัตราการเรียนรู้ชั่วคราวในการคำนวณรอบนั้น: 
    new P(T) = P(T) × β
  3. คำนวณหาความรู้ใหม่หลังทำข้อนี้ด้วยสูตร BKT ปกติแต่ใช้ new P(T) ด้านบน

3. การไหลของข้อมูลทีละฟังก์ชัน (Step-by-Step Data Flow)

ตัวอย่างการคำนวณการคูณเศษส่วน เริ่มต้นด้วยผู้เรียนมีระดับความรู้เดิม P(L_current) = 0.50, ทักษะมี P(T) = 0.20, และโจทย์ข้อนั้นมีเวลาแนะนำ expect_time = 30 วินาที

ขั้นตอนที่ 1: รับข้อมูลเข้าการทำโจทย์ (Attempt Input)
- นายหนึ่ง (ทำเร็ว): ใช้เวลา 15 วินาที, ตอบถูก
- นายสอง (ทำช้า): ใช้เวลา 90 วินาที, ตอบถูก
ขั้นตอนที่ 2: คำนวณความเร็ว (calculate_speed_factor)
- นายหนึ่ง: สัดส่วนเวลา 15/30 = 0.5 (เร็วกว่ากำหนด) → speed_factor = 1.0
- นายสอง: สัดส่วนเวลา 90/30 = 3.0 (ช้ากว่ากำหนด 3 เท่า) → speed_factor = 1.0 / 3.0 = 0.33
ขั้นตอนที่ 3: คำนวณความน่าจะเป็นหลังตอบถูก (posterior_given_evidence)
เนื่องจากได้คะแนนถูกเหมือนกันและเริ่มที่จุดเดียวกัน ทั้งคู่จะได้ค่าความรู้หลังคำนวณเบื้องต้นเท่ากัน:
p_l_posterior = 0.7826 (78.26%)
ขั้นตอนที่ 4: อัปเดตทรานซิชันการเรียนรู้ (apply_learning_transition)
- นายหนึ่ง: effective_p_t = 0.20 × 1.0 = 0.20 → ความรู้ใหม่เพิ่มเป็น 82.61% (ผ่านเกณฑ์เร็วขึ้น)
- นายสอง: effective_p_t = 0.20 × 0.33 = 0.066 → ความรู้ใหม่เพิ่มเป็น 79.71% (อัปเดตเพิ่มช้าลงเพราะติดขัด)

4. การอัปเดตค่า pG และ pS ของโจทย์ด้วย pyBKT (Cron Job)

เพื่อให้ตัวแปรตั้งต้น $P(G)$ และ $P(S)$ ในฐานข้อมูลตรงกับพฤติกรรมจริงของมนุษย์หมู่มาก ระบบจะดึง Log ในฐานข้อมูลมาคำนวณย้อนหลังผ่าน pyBKT ด้วยระบบ Cron Job

ข้อมูล Log ขั้นต่ำที่ต้องจัดเก็บต่อ 1 ครั้งการทำโจทย์:

ฟิลด์ข้อมูล คำอธิบาย ความสอดคล้องกับตารางปัจจุบันใน NestJS
Learner ID รหัสผู้เรียนเพื่อจัดกลุ่มประวัติส่วนบุคคล branch.userId (เชื่อมผ่าน history.branchId)
Problem Name ไอดีประจำโจทย์แต่ละข้อ sessionAndExercise.exerciseId (เชื่อมผ่าน history.sessionAndExerciseId)
Skill Name ทักษะวิชาของข้อสอบนั้น exercise.skillId (เชื่อมผ่าน exercise)
Correctness ผลการตอบ (1 = ถูก, 0 = ผิด) history.isCorrect (แปลง true → 1, false → 0)
Order / Time เวลาเพื่อนำมาจัดคิวเรียงลำดับลำดับก่อนหลัง history.endTime

⚠️ ข้อสังเกตโครงสร้างฐานข้อมูลปัจจุบัน

ตาราง history มีข้อมูลครบถ้วนสำหรับใช้ป้อนให้ pyBKT แล้ว แต่ในตาราง exercise ยังขาดฟิลด์ p_g และ p_s คุณต้องแก้ไขไฟล์ exercise.entity.ts เพื่อเพิ่มคอลัมน์เก็บตัวแปร 2 ตัวนี้เพื่อให้การอัปเดตด้วยระบบ Cron Job สำเร็จ
